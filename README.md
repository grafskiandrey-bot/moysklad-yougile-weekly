# Автоматическая сводка поставок МойСклад → YouGile

По понедельникам **в 09:00 по Москве** GitHub Actions готовит отчёт об ожидаемых поступлениях на МС **с понедельника по воскресенье** и отправляет его в чат задачи **PRO-10131**.

## Важно о безопасности

- **Сделайте этот репозиторий приватным** в Settings → General → Danger Zone → Change visibility → Private. Расписание отправки намеренно **заблокировано для публичного репозитория**.
- Не добавляйте API-ключи в код, README, Issues или сообщения чата. Только **Settings → Secrets and variables → Actions → New repository secret**.
- Скрипт выполняет **только GET** к API МойСклад. В Google Sheets ничего не изменяется.
- В YouGile выполняется POST только для публикации сообщения в чат выбранной задачи.

## Настройка секретов

Создайте в [GitHub Actions Secrets](../../settings/secrets/actions) три записи:

| Secret | Значение |
| --- | --- |
| `MOYSKLAD_TOKEN` | API-токен МойСклад с правами только на чтение заказов поставщикам, позиций и приёмок |
| `YOUGILE_TOKEN` | API-ключ YouGile |
| `YOUGILE_TASK_UUID` | **Внутренний UUID** задачи YouGile PRO-10131 (не номер `PRO-10131`) |

Ссылка на нужную задачу: https://www.yougile.com/team/416b7fa6e94d/#PRO-10131

**Важно:** публичный номер `PRO-10131` и внутренний UUID — разные идентификаторы. Из одной ссылки UUID определить нельзя. Узнайте его через API YouGile/свойства задачи. Скрипт содержит запасной поиск через `task-list`, но автоматическое выполнение намеренно требует `YOUGILE_TASK_UUID`, чтобы исключить отправку в неправильный чат.

Если ключи ещё не настроены, workflow завершится с пояснением об отсутствующем секрете и **не отправит сообщение**.

## Запуск

1. После переключения репозитория в **Private** добавьте три секрета.
2. Откройте вкладку **Actions → Weekly MoySklad receipts to YouGile → Run workflow**.
3. Сначала оставьте `dry_run = true`. Отчёт сформируется в логах Actions, но в чат не отправится.
4. Если даты, количества и артикулы верны, запустите `dry_run = false` один раз. Это опубликует сообщение в чате.
5. В дальнейшем расписание запускается автоматически: **понедельник 06:00 UTC (09:00 МСК)**. GitHub может задержать старт расписания.

## Что учитывается

- Комментарии заказа с ожидаемыми датами прибытия, в приоритете перед обычным полем `deliveryPlannedMoment`;
- период понедельник–воскресенье;
- количественные позиции, включая артикула, которые не поступили полностью;
- проведённые приёмки (если их связи получены через API), иначе по полю `shipped` позиции;
- предупреждения, если дата берётся только из планового поля или в комментарии есть несколько дат партий;
- повторную публикацию той же недели, если метка `[MS-WEEKLY:YYYY-MM-DD]` уже присутствует среди последних сообщений чата.

**Ограничение:** когда комментарий перечисляет отдельные даты и части партии без однозначной связи с артикулами, программа не придумывает распределение и предупреждает об этом. Итоговая дата и количество требуют проверки человеком. При отсутствии даты прихода товар не включается в недельный план.

## Локальная проверка

Требуется Python 3.11+ без сторонних пакетов.

```bash
export MOYSKLAD_TOKEN='...'
python3 weekly_receipts.py --dry-run --date 2026-10-19
python3 -m unittest discover -s tests -v
```

Не публикуйте вывод реального отчёта (в нём внутренние данные закупок) в открытых логах.

## Часто встречающиеся проблемы

- **Task UUID missing:** внутренний ID задачи отличается от ссылки с номером PRO-10131.
- **HTTP 401:** токен истёк, неверный или недостаточно прав.
- **HTTP 403:** права владельца ключа запрещают доступ.
- **Пустой отчёт:** в выбранной неделе нет заказов с датой прибытия, либо комментарии указывают только даты производства.
- **Нет запуска:** проверьте приватность репозитория, доступность Secrets, активность Actions и cron.
